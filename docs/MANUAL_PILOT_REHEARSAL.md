# 첫 수동 실측 리허설

실제 관측 상태: **NOT_RUN**. 양식과 절차만 제공한다. AI 응답·인용 URL·추천률을 생성하지 않는다. LOCAL MOCK과 실제 고객 프로젝트를 분리한다.

## 시작 조건

고객 정보 사용·관측·증빙 보관 동의와 담당자를 확인한다. 환자 정보·진료기록·상담 비밀·비밀번호를 입력하지 않는다. 수집자와 독립 검증자는 서로 다른 사람으로 지정한다. 회사 공개 연락처와 암호화 백업·복원 절차를 확인한다.

질문 10개와 플랫폼 2개, 총 20개 예정 슬롯으로 시작한다. 사람이 ChatGPT·Gemini·네이버 AI 중 접근 가능한 두 화면을 선택한다. 자동 호출 명령이 아니다. 현재 Pre-Scan 고정 세트는 30개이므로 후보30개를 확정하고 이번에는10개만 관측하며 나머지를 미측정으로 남긴다. 수집20건도 독립 검증 전에는 확정 통계가 아니다.

## 실행 순서

1. 확인된 고객 정보로 생성 질문을 검수하고10개 원문을 확정한다. 질문·화면·검색·지역·로그인 조건을 Baseline과 Follow-up에서 유지한다.
2. 사람이 소비자 AI 화면을 직접 열고 새 대화·로그인·위치·검색 여부를 기록한다. 모델이 표시되지 않으면 `미표시`로 남기며 추측하지 않는다.
3. 원문 질문을 제출하고 제출·답변 기록 시각을 시간대 포함 ISO 8601로 기록한다. 답변 원문을 수정하지 않고 실제 인용 URL만 기록한다. 인용이 없으면 빈 목록이다.
4. 질문·모델 표시·답변·인용이 확인되는 스크린샷을 만든다. 개인정보가 있으면 업로드하지 않는다. 해당 고객 프로젝트에 3MB 이하 PNG/JPEG/WebP를 첨부한다.
5. 수동 관측을 저장하고 재조회하여 원문·시각·조건·첨부가 일치하는지 확인한다. 실패·접근 제한·응답 없음은 실패/미측정으로 기록한다.
6. 별도 검증자가 화면 증빙과 원문·URL·업체 식별·조건을 대조한다. 불일치는 REJECTED 또는 보류로 남기고 원문을 덮어쓰지 않는다. 독립 검증자가 없으면 VERIFIED 처리하지 않는다.
7. 고정 Snapshot을 만들고 플랫폼별 분모·제외 사유를 검수한다. 부분/작은 표본의 한계를 보고서에 남기고 추천·예약 증가나 인과 효과를 단정하지 않는다.
8. PDF 내부 검수·승인 후 전달은 사람이 수행한다. 홈페이지는 별도 고객 승인·규정 검토 후 사람이 적용하고 전후 증빙을 남긴다. 자동 이메일·게시·계약은 수행하지 않는다.

## 직원 시간·원가 기록

## 중단 조건

파일 해시 불일치, 담당 외 고객 자료 노출, DB/PDF 저장 실패 또는 확정 분모 오류가 발생하면 전달을 중단한다. 원본·실패 기록을 보존하고 격리 복원으로 원인을 확인한다. 실패를 성공으로 바꾸어 보고하지 않는다.
