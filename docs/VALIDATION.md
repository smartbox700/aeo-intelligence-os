# 검증 기록 · 2026-10-08 · 2단계

## 기존 프로그램 점검

고객 CRUD·질문·수동 응답·출처·CSV·기본 홈페이지 진단·과제가 실제 구현되어 있었다. PostgreSQL 연결·저장·재조회가 동작했다. 기존 단위 10개와 핵심 브라우저 2개가 통과했다. 자동 API 수집은 인터페이스만 있었고 문맥 추천 분석은 없었다. 기존 홍제 A치과 DEMO 응답 5개를 보존했다.

## 2단계 검증

- TypeScript 검사 및 Next.js 프로덕션 빌드 통과.
- Vitest 단위 34개 통과: 기존 분석·SSRF, 업체 문맥/부정/유사명/명시 번호/검토, OpenAI 검색 메타데이터·인용·사용량·실패 파싱, 배치 제한·중복 방지·실패 저장, robots, 유효 지표 제외 조건. 기본 실행에서는 PostgreSQL 조건부 통합 1개를 건너뛴다.
- 조건부 실제 PostgreSQL 통합 1개 별도 통과: 모의 어댑터 응답을 DEMO로 표시하고 배치·원문·인용·업체 분석을 DB에 저장·재조회. 기존 프로젝트 보존을 확인하고 검증용 프로젝트만 삭제.
- Edge 핵심 흐름 3개 통과: 기존 고객 CRUD·수동 입력·새로고침·CSV·과제, 원문 보존·소속/Origin/SSRF 제한, 신규 실측 연구소·키 미설정 비활성화·실측 질문·DEMO 업체 담당자 수정·수정 이력·CSV 필드.
- 공개 홈페이지 example.com 및 비교 example.org 실제 HTTPS 진단: 각 27개 검사, 경쟁사 비교 SUCCESS, 과제 15개 저장. 검증 전용 프로젝트만 삭제. 실제 병원 정보는 검증하지 않았다.
- PC 1440px·모바일 390px 화면 확인 및 JavaScript 오류 없음.
- Prisma 스키마를 추가 적용했으며 DB 삭제·초기화하지 않았다. 초기 서버의 Prisma DLL 잠금 문제는 앱 종료 후 재생성하여 해결했다.

## 미검증 및 환경

**OPENAI_API_KEY가 없어 실제 OpenAI 호출·실제 웹 검색 답변·계정별 모델 권한·청구는 검증하지 못했다.** 모의 API 응답을 실측 성공으로 주장하지 않는다. 키를 설정한 뒤 질문 1개·반복 1회로 사용자 확인이 필요하다. 기본 모델은 공식 문서에서 Responses/web_search 지원을 확인한 gpt-5.6-luna이며 서버 환경변수로 변경한다.

Docker 엔진은 실행되지 않아 Docker 실행 미검증. PostgreSQL 18.4는 embedded-postgres 개발 도구로 실제 실행했다. 개발 DB는 루프백·비밀번호 방식이며 임시 경로 데이터에는 별도 백업이 필요하다. Gemini·네이버 API, 인증·다중 사용자·대규모 부하·실제 고객 의료 정보의 진위·법적 적합성은 미검증 또는 미구현이다.

프로덕션 E2E는 먼저 build한다. `.env`는 Git 제외, 실제 키·로컬 데이터는 커밋하지 않는다. 설정과 실행 방법은 README를 따른다.

## 실제 OpenAI 요청 추가 확인 · 2026-10-08

사용자가 키 사용을 승인한 뒤 서버 .env에 설정하고 재시작했다. 키는 출력하지 않고 Git 제외를 확인했다. 홍제역 질문 1개·반복 1회로 실제 Responses API 요청을 수행했으나 HTTP 429, 남은 크레딧 없음 오류로 실패했다. 배치 d88d8cf0-29c9-41c5-966f-14a8e24b07c6의 API_OBSERVATION 실패 기록을 DB 저장 후 재조회했다. 검색 미실행·원문 없음이며 유효 지표에서 제외된다. 자동 재시도하지 않았다. 기존 DEMO 5개를 보존했다. 실제 웹 검색 응답 수집 성공·업체 추출·인용 저장은 여전히 미검증이며 API 크레딧 충전 후 최소 호출 확인이 필요하다. 키가 채팅에 공유되어 교체를 권고했다.

## 3단계 최종 검증 · 2026-10-08

- 기존 PostgreSQL 구조·고객 CRUD·질문/응답·ProviderAdapter·원문 보존을 재사용. DB 초기화/삭제 없이 JSON payload를 확장했다. 기존 홍제 A치과 DEMO 응답 5개와 2단계 HTTP 429 실패 응답을 보존했다.
- LIVE_AI_ENABLED=false를 서버에 적용. 키가 등록된 상태에서도 제공사 available=false를 확인. 측정 서비스·OpenAI 어댑터·실제 전송 함수 모두 요청 전에 차단한다. 단위 spy에서 전송 0회, 브라우저의 measure 요청은 HTTP 400이며 배치 예약을 하지 않는다. 이번 단계 유료 AI 호출 없음.
- TypeScript·프로덕션 빌드 통과. Vitest 단위 50개 통과. 기본 실행에서 조건부 PostgreSQL 통합 1개는 제외하고 별도 실행하여 통과했다.
- Edge E2E 4개 통과: 기존 CRUD·응답·CSV·보안, 실측 대기와 업체 수정, 3단계 DEMO 수동 입력·추천 문맥·비교·처방·가중치 검증·소속 제한·담당자 배정·검토 승인·작업 이력·수정 기록·DB 재조회. 테스트 전용 데이터만 정리했다.
- 신규 안전 테스트: robots 차단·미확인 시 본문 요청 없음, 리디렉션의 정책 재검사, 내부 DNS 목적지 차단, 두 화면의 공유 동시/간격 제한. 수동 예약 확인은 근거·시각 없으면 거부. 불확실한 수동 업체 식별은 지표에서 제외.
- 공개 예제 example.com/example.org를 유료 AI 없이 실제 비교했다. LIVE 웹 검사 2개 페이지 스냅샷·비교 SUCCEEDED·격차 12개·과제 12개를 PostgreSQL에 저장·재조회. 검증용 프로젝트만 삭제했다. 실제 병원 홈페이지·의료 정보는 검사하지 않았다.
- 홍제 A치과에 DEMO 가상 HTML 비교 스냅샷과 격차·처방 10개를 추가했다. 실제 사이트 진단이나 마케팅 성과로 해석하지 않는다. 화면에서 DEMO를 선택해야 보인다.
- PC 1440×900·모바일 390×844 화면 확인, JavaScript 오류 0개·전체 화면 가로 넘침 없음. 최초 신규 E2E는 확장 메뉴가 화면 밖에 있어 타임아웃됐다. 사이드바 스크롤 수정 후 전체 테스트가 통과했다.
