# CITED 공개 화면과 수동 진단

기존 운영 OS, 인증, PostgreSQL, 안전한 외부 요청과 관측 원문 관리 기능을 유지한다. 공개 SaaS 배포는 이번 작업에 포함하지 않는다.

## 화면

- `/`: 비로그인 방문자는 CITED 랜딩, 기존 로그인 사용자는 기존 OS 첫 화면을 유지한다.
- `/welcome`: 로그인 여부와 관계없이 브랜드 홈을 표시한다.
- `/os`: 기존 직원·고객 권한을 확인한 운영 화면. 미인증 사용자는 로그인으로 이동한다.
- `/diagnosis`: 브랜드·지역·서비스로 10/50개 질문을 생성하고 플랫폼별 관측을 직접 입력한다.
- `/report`: 초안 또는 권한이 있는 고객 프로젝트의 저장된 리포트와 JSON 다운로드, 브라우저 인쇄를 제공한다.
- `/blog/aeo-marketing-1`: 출처 없는 시장 수치와 고객 성과를 제외한 실무 가이드.

## 측정 정의

질문 50개는 브랜드 10, 추천 8, 정보 15, 선택 기준 10, 지역 7개다. 시작 진단 10개는 각각 2/4/2/1/1개다. 5개 플랫폼의 관측 슬롯을 각각 관리한다. 자동 API 요청은 없다. 각 관측은 원문·관측 시각(한국 시간)·모델/모드 및 조건을 입력하고 확정해야 집계된다. 수정하면 초안으로 돌아간다. 미측정은 분모에서 제외하며 무관측 비율은 0% 대신 미측정이다. 추천률은 추천형 질문만 집계한다. 사용자 입력이므로 제3자가 검증한 실적이 아니다.

## 저장 및 운영 범위

비로그인 진단 초안은 sessionStorage로 현재 탭에 임시 보관한다. OWNER/MANAGER가 로그인 후 고객 프로젝트에 저장하면 같은 저장소의 고객 정보에 진단 버전이 보존되고, 질문과 확정 원문이 기존 OS에 MANUAL_OBSERVATION으로 연결된다. 고객명 일치·프로젝트 권한·원문과 관측 조건을 검증한다. 같은 입력을 반복 저장해도 중복 관측을 만들지 않으며 수정 원문은 새 기록으로 보존한다. ANALYST는 허용된 고객의 진단을 조회할 수 있고 저장은 금지된다. 전화번호·대표자명·법률 상담 비밀은 수집하지 않는다. 응답 입력에도 민감 정보는 넣지 않는다. JSON 다운로드에 원문이 포함되므로 외부 전달 전 검토한다. 탭 종료 전 다운로드 또는 PDF로 보관한다. JSON은 공개 진단 형식이며 기존 OS 일괄 업로드 형식과 동일하지 않다. 진단·리포트·OS 이동 시 고객 선택을 유지한다. 수동 체크는 진단 버전에 보존하며 기존 OS 자동 분석과 혼합하지 않는다. 공식 출처 URL 없이 체크한 인용을 OS 검증된 출처로 만들지 않는다. 공유 링크·온라인 상담 접수·결제는 후속 작업이다.

## 영업 표현

175만원 파일럿, 월 149만원은 제안 가격으로 표시한다. 범위·외부 비용·부가세 조건은 계약 전 확정한다. 출처 없는 73%/38%/48%, 고객 이름을 넣은 미검증 성과, 40% 보장, 1위와 할인율 표현은 사용하지 않는다. 도메인 소유권과 이메일 개통을 가정하지 않는다. 공개 배포 전 최초 OWNER 설정 경로, 계정 보호, 저장 정책, 상업용 호스팅 조건을 별도 검토한다.

## 빌드

기존 검증 복사본이 있는 output/tmp/data를 TypeScript 검사 범위에서 제외한다. 원본 src/tests의 검사는 유지한다. Next.js를 과거 버전으로 내리지 않는다.

## 검증 기록 · 2026-10-11

- TypeScript 검사와 Next.js 프로덕션 빌드 통과.
- 단위 테스트 128개 통과, 조건부 5개 생략.
- 공개 랜딩·미측정 리포트·원문 필수 검증·관측 저장·새로고침·플랫폼 분리·JSON 다운로드·OS 미인증 차단 흐름 통과.
- 기존 고객 CRUD·질문/응답 저장·집계·CSV·원문 보존·SSRF·출처 보호 흐름 통과.
- 데스크톱과 390px 모바일 화면에서 랜딩 표시와 가로 넘침 확인.
- 기존 Prisma/파일 저장 경로에 대한 Turbopack 동적 파일 추적 경고 3개는 남아 있다. 공개 배포 전 배포 파일 범위를 확인해야 한다.
- 도메인 연결, 상업용 호스팅, 온라인 결제·계약·상담 접수는 미실행.

## 고객 연결 검증

`node scripts/test-cited-integration.mjs`는 통합 백업을 별도 DB로 복원하고 output/stage7-5 아래 격리 실행 폴더에서 브라우저 테스트를 실행한다. 원본 DB는 변경하지 않는다. 진단→새 고객 저장→중복 저장 방지→고객 OS→저장된 리포트→진단 이어하기와 기존 핵심/보안 흐름 4개가 통과했다. 테스트 복원 DB와 실행 폴더는 검증 기록으로 보존한다.
