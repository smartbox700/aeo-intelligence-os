# 4단계 · 무료 AI 관측·추천 비교·성과 검증 v1.0

기존 PostgreSQL, 고객사, 질문, 응답 원문, 분석·과제를 유지했다. DB 초기화나 기존 데이터 이관을 수행하지 않았다. 고객·질문 관리, 수동 응답 저장, Provider Adapter, 홈페이지 안전 전송, 경쟁사 격차·우선순위·작업 이력은 기존 모듈을 재사용한다. 4단계는 유료 API를 호출하지 않는다.

## 사용 방법

현재 화면: http://127.0.0.1:3000/ . 홍제 A치과를 선택하고 **AI 실측 연구소**를 연다.

1. 요청한 홍제역 질문 5개를 선택하거나 `홍제역 질문 5개 준비`를 누른다. 기존 동일 질문은 중복하지 않는다.
2. ChatGPT 웹 검색, Gemini 소비자용 검색, 네이버 AI 브리핑 중 플랫폼을 선택한다. 질문을 복사하고 공식 AI 서비스 열기를 누른다.
3. 사용자가 서비스에 직접 로그인·실행한다. 이 앱은 로그인·스크래핑·CAPTCHA 우회·자동 질문 전송을 하지 않는다.
4. 표시된 모델 또는 `미표시`, 실제 질문, KST 입력/기록 시각, 국가·지역, 검색 사용 여부, 수집자, 원문, 실제 표시된 출처 URL을 입력한다. 소비자 화면 수집 확인 후 저장한다.
5. 저장 기록을 펼쳐 원문·업체 문맥·명시적 소개 번호·인용·예약/구매 링크를 확인한다. 업체 식별을 수정할 때 원문은 유지하고 분석 이력을 추가한다.
6. `같은 질문 · 다음 플랫폼`으로 질문과 지역을 유지해 연속 입력한다. 새 플랫폼의 모델 표시와 시각을 다시 확인한다.
7. AI별 가시성 비교에서 분모/표본과 실제 원문을 확인한다. 유효 관측이 있으면 개선 과제를 생성하고 기존 AEO 격차 진단·최적화 작업에서 관리한다.

선택 증빙은 PNG/JPEG/WebP, 3MB 이하, 최대 5개다. 서버 파일명은 무작위이며 프로젝트 소속을 검사한다. 이미지는 OCR·내용 읽기·자동 추출을 수행하지 않는다. 관측 원문과 별도 파일/해시로 저장한다. `data/evidence/`는 Git 제외 대상이다.

제3자 검토는 별도 검토자명·근거·상태·시각·이력의 담당자 입력 기록이다. 동일 관측자 이름으로 검토 완료를 기록할 수 없다. 로컬 단일 사용자 MVP에는 신원 인증이 없으므로 독립 감사나 실제 제3자의 신원 확인을 보장하지 않는다.

## 데이터와 지표

신규 소비자 관측은 **CONSUMER_UI_MANUAL**, API는 **API_OBSERVATION**, 테스트는 **DEMO**로 분리한다. 기존 MANUAL_OBSERVATION/MANUAL_UI/API 기록은 그대로 유지하며 자동으로 신뢰도가 높은 새 유형으로 변환하지 않는다. 기본 대시보드는 CONSUMER_UI_MANUAL이다.

소비자 화면 출처는 관측자의 자기 보고다. 제3자 검토 여부는 별도이며 미검토만 모아도 원문 조건이 유효하면 자기 보고 표본으로 집계한다. 제3자 검토 완료만 필터링할 수 있다. 검색 미사용/미확인, 수집 화면 미확인, 업체 식별 검토 필요, 검증 거부는 유효 표본에서 제외한다. 새 DEMO 소비자 관측에도 검색·식별 유효성을 검사하되 실제 성과와 섞지 않는다.

| 지표 | 분자 | 분모 |
|---|---|---|
| 고객사 언급률 | 정확히 식별된 고객사 등장 응답 | 같은 유형·플랫폼·기간의 유효 응답 |
| 추천 후보 포함률 | 고객사를 추천 문맥으로 소개한 응답 | 유효 응답 중 문맥 분석 READY 응답 |
| 첫 번째 소개 비율 | 고객사의 명시적 소개 번호가 1인 응답 | 명시적 번호가 있는 추천 후보 목록 응답 |
| 자사 URL 인용률 | 등록 홈페이지와 동일 호스트 출처를 가진 응답 | 유효 응답 |
| 경쟁사별 언급률 | 해당 등록 경쟁사가 등장한 응답 | 유효 응답 |
| 질문/질문 유형/기간 변화 | 해당 그룹의 언급 응답 | 해당 그룹의 유효 응답 |

소개 번호가 없는 답변은 임의 순위를 생성하지 않는다. 첫 번째 소개 분모에도 넣지 않는다. 시장점유율, 플랫폼 전체 추천 확률, 실제 이용자 수, 치료·구매 성과는 이 표본으로 추정하지 않는다.

## 동일 조건 재측정

Baseline·Follow-up 메뉴에서 질문·3개 플랫폼·플랫폼별 모델 표시·국가·지역·검색 사용 확인·1~5회 반복 계획을 저장한다. 실제 관측 수와 계획 수는 별도다. 각 관측을 계획/단계/반복 번호에 연결한다.

질문 원문, 화면, 모델 표시, 국가/지역, 검색 여부, 데이터 유형이 계획과 일치하고 양쪽 응답 모두 집계 유효한 대응 쌍만 비교한다. 조건 변경은 원문 링크와 경고를 표시하며 대응 비교에서 제외한다. `미표시` 모델은 동일 모델을 보장하지 않는다. 30쌍 미만은 내부 작은 표본 주의를 표시하며 30쌍 이상도 통계적 유의성·인과 효과를 보장하지 않는다. 계획 슬롯 중복 입력은 차단한다.

## 일괄 입력과 보존

CSV/JSON 3MB, 최대 50행. 한 행이라도 질문/프로젝트/증빙/시간/URL/계획 검증에 실패하면 전체를 저장하지 않는다. 입력 UUID와 조건/원문 해시로 중복을 막고 같은 키의 다른 원문은 거부한다. 내보낸 JSON에는 분석·검토·예약/구매 링크도 포함한다. 재입력으로 제3자 검증 상태를 조작할 수 없다.

CSV는 따옴표·줄바꿈·URL 배열을 지원한다. 수식으로 시작하는 셀은 스프레드시트 실행 방지 문자를 붙이므로 완전한 원문 보존 교환은 JSON을 사용한다. DB 원문은 변경되지 않는다. 기존 고객 수정은 신규 연구 계획·증빙·무료 API 기록을 보존한다.

## 비용 차단과 Gemini 준비

`.env`에 `LIVE_AI_ENABLED=false`, `FREE_GEMINI_ENABLED=false`가 설정되어 있다. 키 존재만으로 실행되지 않는다. 유료 API는 측정 서비스, OpenAI 어댑터, 안전 전송 계층에서 차단한다. 무료 준비 점검도 명시적 승인 없이 받지 않는다.

Gemini 공통 Provider Adapter는 `gemini-2.5-flash`, `google_search`, Grounding 출처/메타데이터, 토큰 사용량을 처리한다. 안전 전송은 audit.ts의 고정 API URL·DNS/IP 고정·시간/본문 제한을 사용한다. 별도 활성 설정, 실행 승인, 만료되지 않은 서버 검증(무료 등급·결제 비활성·모델 권한)이 모두 필요하다. 기본 일일 2회(최대 10), 60초 간격, 재시도 0회, 429 이후 해당 일 실행 중단, 유료 모델 전환 없음. 어댑터 실행 예약/완료/사용량은 전달된 영속 기록 콜백에 저장하도록 구성했다.

**현재 미구현/미검증:** 계정별 무료 등급을 공식 서버 수단으로 증명하는 커넥터와 검증 후 실제 실행 서비스 연결. 공개 요금표나 사용자의 체크박스는 무료 계정 증거로 인정하지 않는다. 따라서 실제 무료 Gemini 버튼은 비활성이고 준비 점검은 BLOCKED/networkCalls=0을 저장한다. 키가 없어도 다른 기능은 작동한다. 실제 Gemini API 호출은 수행하지 않았다.

공식 표에서 2.5 Flash의 무료 등급과 Google Search Grounding 무료 제공을 확인했지만 계정별 한도는 별도다. [Google 요금표](https://ai.google.dev/gemini-api/docs/pricing), [프로젝트별 호출 제한](https://ai.google.dev/gemini-api/docs/rate-limits), [Grounding 문서](https://ai.google.dev/gemini-api/docs/google-search). 2.5 Flash는 신규 프로젝트 접근이 제한될 수 있으며 다른 모델로 자동 변경하지 않는다. [모델 접근 안내](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash).

네이버 일반 검색/지역/쇼핑 API와 AI 브리핑은 별개다. 소비자 브리핑은 수동 입력만 지원한다.

## 실행과 검증

DB가 꺼져 있으면 별도 터미널에서 `node scripts/local-postgres.mjs`. 앱은 `pnpm build`, `pnpm start` 또는 개발용 `pnpm dev`. 기존 DB를 초기화하지 않는다. 상세 명령은 README 참고.

검증 명령: `pnpm typecheck`, `pnpm test`, `pnpm test:e2e`, `pnpm build`. 조건부 PostgreSQL 통합 테스트는 PowerShell에서 `$env:AEO_TEST_POSTGRES='1'; pnpm exec vitest run tests/postgres.integration.test.ts`. 테스트는 자신이 만든 DEMO 프로젝트·증빙만 정리하며 기존 고객 데이터는 보존한다.

다음 우선순위: 사용자의 실제 소비자 화면 측정, 별도 검토자의 증빙 대조, 동일 조건 Follow-up 표본 축적, 무료 계정 검증 커넥터 검토. 인증·권한·감사로그 없이 공개 배포하지 않는다.

### 2026-10-08 최종 검증 결과
타입 검사와 Next.js 프로덕션 빌드 성공. 단위 테스트 64개 성공(조건부 PostgreSQL 1개는 기본 실행에서 제외), 별도 PostgreSQL 통합 테스트 1개 성공, Edge 브라우저 핵심 흐름 5개 성공. 최종 실패 0개. CSV null/키 정규화와 검색 상태 선택 접근성 오류는 수정 후 재검증했다. 질문 복사, 3개 플랫폼 입력, 원문·출처·증빙·검토 저장/재조회, 비교, CSV/JSON 중복 재입력, 전후 경고, 과제 연결 및 유료·무료 미검증 호출 차단을 확인했다.
홍제 A치과: 요청 5문항 준비(기존 동일 1문항 + 신규 4문항), 3플랫폼 × 1회 × Baseline/Follow-up 계획. 기존 응답 6건, 진단 2건, 과제 13건을 유지했다. 실제 소비자 관측은 0건으로 성과 미측정. 이번 개발의 실제 OpenAI/Gemini API 호출은 0회다. 무료 Gemini 계정 증명·실제 호출·실제 소비자 3개 서비스 답변·제3자 신원·마케팅 효과는 미검증이다.
