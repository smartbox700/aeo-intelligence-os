# 3단계 · 경쟁사 역분석 및 AEO 최적화 엔진

## 비용 차단

서버의 LIVE_AI_ENABLED=false가 기본입니다. 값이 누락되거나 오타여도 차단합니다. 키가 있어도 배치 예약·OpenAI 어댑터·HTTPS 전송 전에 거부하며 DNS/유료 요청을 하지 않습니다. 관리자 화면은 API 실측 대기를 표시합니다. 이번 단계에서는 true로 변경하지 않습니다. 모의 제공사 단위 테스트는 네트워크 대신 spy를 사용합니다.

## 화면 사용

1. 고객사 관리에서 고객·경쟁사 공식 URL, 확인된 주소, 예약·구매 URL을 등록합니다. URL 등록만으로 소유권·사실이 검증되지는 않습니다.
2. AI 응답 분석에서 질문·플랫폼·KST 시각·지역·원문·출처·관찰 추천 업체를 입력합니다. 새 수동 관측은 MANUAL_OBSERVATION, 과거 MANUAL_UI는 별도 보존합니다. 실제 예약 가능 확인은 공식 화면/전화 등 근거와 확인 시각을 함께 입력합니다. AI 답변만으로 확정하지 않습니다.
3. 경쟁사 분석에서 지역 전문 서비스 또는 상품 판매 프로필을 선택·저장합니다. 공개 홈페이지 비교 또는 DEMO 가상 HTML 비교를 실행합니다. DEMO는 실제 사이트 검사·진료 정보가 아닙니다.
4. AEO 격차 진단에서 고객 상태·경쟁사 관측·관련 질문·근거 URL·필요성·수정·검토·재측정을 확인합니다.
5. AEO 최적화 작업에서 담당자·기한·상태·검토 근거를 저장합니다. 검토가 필요한 처방은 승인 근거 없이 완료할 수 없습니다. 수정 이력은 누적됩니다.
6. 개선 전후 비교에서 같은 질문·플랫폼·모델·지역·유형, 기간과 기준일(KST)을 선택합니다. 웹사이트 수정 URL·내용·검증 기준을 기록합니다. DEMO 수정 이력도 분리합니다. 이력은 담당자 기록이며 앱이 실제 사이트를 자동 수정하지 않습니다.

## 검사와 한계

지역 서비스는 명칭·주소·연락처·서비스 범위·전문가 확인 경로·FAQ·예약에, 상품 판매는 상품명·제조사·모델·규격·가격·배송·구매 조건·Product JSON-LD에 초점을 둡니다. 공통 기술 항목은 접근·색인·본문·제목·구조입니다. 의료·법률 업종의 표현은 담당자 광고 규정 검토를 표시합니다.

최대 경쟁사 2곳, 업체마다 홈페이지와 관련 내부 링크 페이지 최대 2곳을 검사합니다. robots와 sitemap도 확인합니다. robots.txt를 먼저 조회하고 AEOIntelligenceOS 경로 차단·정책 미확인 시 본문 수집을 중단합니다. 리디렉션의 IP와 경로 정책도 다시 검사합니다. 기본 포트 HTTP(S), 자격증명 URL 금지, DNS 공개 IP 확인 및 IP 고정, 내부/예약 IP 차단, DNS 4초·HTTP 전체 8초·1MB·리디렉션 3회 제한을 사용합니다. 두 웹 검사 화면은 동시 검사 1개·프로젝트당 1분 제한을 공유하며 완료된 LIVE 진단 시각도 확인합니다. 다중 프로세스 공용 제한은 후속 작업입니다.

본문 키워드·링크·JSON-LD 기본 구조는 정보 단서입니다. 전문성·가격·진료·배송 조건의 진위, 예약 목적지 동작, 실제 색인 여부를 자동 인증하지 않습니다. 전체 사이트 크롤링·JS 렌더링·전체 Schema.org 의미 검증·자동 규정 판정은 미구현입니다. 상업 플랫폼 API·로그인 페이지·차단 우회는 제공하지 않습니다. 주요 페이지에서 발견한 정보는 해당 URL과 관측 시각에 한정됩니다.

## 우선순위 계산

가중치 기본값은 정확성/신뢰성 30, 질문 관련성 25, 기술 20, 실제 인용/격차 15, 전환 경로 10입니다. 프로젝트 설정에서 합계 100인 값을 저장합니다. 각 진단 항목별 0~1의 규칙 계수를 곱하고 소수 1자리로 반올림한 구성 점수 합이 총점입니다. 상세 계수는 src/lib/optimization.ts, 프로필·가중치는 optimization-config.ts에 분리했습니다. 경쟁사 정보 단서만 있으면 인용 영역 계수 0.5, 그 경쟁사 공식 호스트가 해당 유형의 유효 응답에서 인용됐다면 1입니다. 질문과 직접 연결되는 등록 질문이 없으면 관련성 0입니다. 기술·전환은 해당 항목일 때만 부여합니다. AI 추천 확률 또는 비공개 알고리즘 점수가 아닙니다.

과거 진단에는 프로필·가중치·버전·근거·점수 스냅샷을 저장합니다. 설정 변경은 다음 검사에만 적용합니다. 관측 사실 → 근거 → 개선 가설 → 작업 → 검증을 분리합니다. 경쟁사 특징을 추천 원인으로 단정하지 않습니다.

## 데이터와 검증

PostgreSQL 기존 관계/JSON payload를 재사용했습니다. ClientEntity에는 프로필·가중치·수정 이력, WebsiteAudit에는 페이지·격차·출처 스냅샷, OptimizationTask에는 점수·담당자·검토·이력, AIResponse에는 수동 관찰·예약 확인을 추가합니다. DB 초기화나 스키마 삭제가 필요하지 않습니다. 원문은 기존 불변 컬럼으로 보존합니다.

DEMO는 기본 성과에서 제외합니다. 수동 관측에서도 불확실한 업체 식별은 유효 분모에서 제외하며 담당자 확인이 필요합니다. 추천은 부정·배경과 구별하고 명시적인 원문 번호만 소개 위치로 기록합니다. 이름 입력만으로 없는 업체를 생성하지 않습니다. 새 수동 응답에는 질문 원문 스냅샷도 저장합니다.
