5단계 테스트는 **홍제 A치과, 서울 B법무법인, C브랜드 고체방향제의 가상 DEMO**에서 온보딩부터 동일 조건 3플랫폼 Baseline/Follow-up·승인·완료 증빙·승인 보고서까지 검사했다. 직원 세 역할의 다른 고객 접근 차단, 금융 자료 비노출, VIEWER 초안 차단, 익명 API 차단, 계정 비활성화에 따른 세션 폐기, 승인 보고서의 SHA256/HTML 불변을 확인했다.

초기 통합 시험은 마지막 화면의 버튼 이름을 잘못 지정해 제한시간으로 실패했다. 명칭을 수정한 재실행은 통과했다. 회귀 시험 하나는 삭제 후 첫 고객에 대한 가정이 새 DEMO 고객과 충돌했으며, 기존 샘플 ID를 명시한 재실행으로 통과했다. 기능이 실제 성공했다고 표시하기 위해 모의 응답을 실제 관측으로 바꾸지 않았다.

자동 승인 검토가 이름 조건에 따른 잔여 테스트 프로젝트 삭제를 거부했다. 해당 삭제는 실행하지 않았다. 초기 실패 시험의 DEMO 고객 3개는 명확히 DEMO로 유지되어 실제 고객·마케팅 지표의 기본 집계에서 제외된다. 성공한 시험에서 생성한 별도 임시 프로젝트와 격리 인증 계정은 기존 테스트의 종료 처리로 정리했다.

개발 전 관계형 JSON 백업과 읽기 전용 대조 결과: 기존 고객 **1개**, 질문 **13개**, 응답 **6개**, 진단 **2개**, 과제 **13개**의 ID 및 내용 보존. 응답 원문/응답 payload/질문/진단/과제/고객 payload 대조 통과. 기존 실제 소비자 응답을 새로 만들어 넣지 않았다. 세션/직원 테이블과 운영·보고서 JSON 열만 추가했다. 대조 기록은 Git 제외 경로 `data/backups/stage5-preservation.json`에 있다.

로컬 최초 OWNER는 개발자가 임의로 만들지 않았다. 사용자가 `/login`에서 등록해야 한다. 시험 계정은 `e2e-*` 인증 영역을 사용했으며 실제 로컬 영역과 다르다.

이번 개발에서 유료 AI API 호출 **0회**. 실제 API 성공, 실제 AI 추천 성과, 실제 고객 승인이나 홈페이지 게시 성공은 보고하지 않는다.
