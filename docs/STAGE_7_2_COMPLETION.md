## 3. 질문120개 생성 방식

`src/lib/query-templates.ts`에 치과10개 의도별12개 독립 정보/의사결정 템플릿을 정의했다. 지역, 확인된 진료 분야를 넣어 로컬에서 생성한다. 임플란트·충치·스케일링·보철 등의 서비스와 치과 업종을 확인한다. 단순 서비스 단어 치환으로 질문 수를 늘리는 방식 대신 검사·기간·재료·보험·내원·선택·시설·운영·예약·사후관리 등 서로 다른 질문 목적을 사용했다.

결과에는 “검색의도 기반 가설 질문”을 표시하며 실제 검색량/빈도를 생성하지 않는다. 공식 URL은 사용자 확인 체크와 HTTP(S) 형식 검증만 수행한다. 프로그램이 외부 사이트 진위를 자동 인증하는 것은 아니다.

정규화는 NFKC·공백·문장부호/기호 제거를 사용한다. 생성 중 정규화 중복은 제거하고 수동 추가/수정의 중복은 오류로 알려 저장하지 않는다. 유사성은 단어 집합 Jaccard 규칙의 후보 표시이며 완전한 의미 동일 판정이 아니다. 부적합/과장/타업종 주제는 사유를 표시하고 제외하며 내용을 수정해 새 버전으로 다시 검토할 수 있다.

서비스가 부족하거나 해당 업종의 자동 템플릿이 준비되지 않았으면120을 임의로 채우지 않고 부족 안내와 수동 편집을 제공한다. LEGAL/BRAND/ECOMMERCE는 별도 설정 구조와 제외 규칙을 준비했지만 자동 문장 템플릿은 아직 비활성이다. 치과 질문을 다른 업종에 자동 적용하지 않는다.

## 4. 대표30개 선정 알고리즘과 버전

`selectQueries`는 포함 후보를 의도별로 나누고 round-robin으로 다양성을 확보한다. 치과120개 사례는10의도에3개씩 총30개를 추천한다. 내부 점수는 상담·예약 등의 의사결정 의도, 지역 포함, 서비스 태그, 측정 목표 단어 관련성을 사용한다. 같은 정규화 문장/유사 후보를 우선 피하며 불가피한 유사 후보에는 검토 필요 이유를 기록한다. 검색량·추천 확률·최적 성과 점수가 아니다.

사용자는 추천 체크를 교체하고 선정 근거를 입력할 수 있다. 확정은 해당 지도 버전의 고유한 포함 질문30개만 허용한다. 지도 수정/추가/제외/재포함은 이전 지도 사본을 변경하지 않고 새 버전을 만든다. 문장이 바뀌면 새 질문 ID를 부여한다. 확정 세트에는 질문 원문·태그·선정 이유의 사본을 저장한다. 기존 측정 계획/원문/질문 스냅샷은 유지하며 새 확정은 별도 세트 버전이다.

## 5. 관측 데이터 입력

Pre-Scan은 소비자 웹 수동 관측이며 ChatGPT 웹 검색·Gemini 소비자 웹 서비스·네이버 AI 브리핑을 각각 구분한다. API 출력은 이 계획에 섞지 않는다. 질문30×플랫폼3=90개 슬롯을 만들지만 응답은 자동 생성하지 않는다.

입력에는 고정 질문 ID/원문, 플랫폼, 모델 표시, 국가/지역, 실제 질문 제출/답변 기록 시각, 검색 사용, 원문, 실제 인용 URL, 관측자, 실제 화면 수집 확인, 선택 스크린샷 증빙 ID를 기록한다. 증빙은 기존 이미지 업로드 API로 연결하고 OCR/자동 추출은 하지 않는다. 실제 웹 서비스는 사용자가 직접 열고 복사/입력한다. 자동 로그인·CAPTCHA 우회·무단 수집을 구현하지 않았다.

미측정 슬롯 CSV 양식을 다운로드하여 실제 값을 작성하고 한 번에50행 이하로 나누어 가져올 수 있다. 90개 전체는 여러 묶음으로 수집한다. 각 묶음은 모든 행의 프로젝트/질문/계획/화면/고정 원문/형식 검증 후 원자 저장한다. 동일 입력 키/동일 내용의 재전송은 재사용하고 같은 키의 변경이나 같은 슬롯의 다른 입력은 거부한다.

## 6. 진행률과 재개

질문 풀 개수·선택 질문30·플랫폼 수·예정 슬롯 수·수집 수·검증 완료·검증 대기·실패/제외·미측정을 구분한다. 수집 완료율과 검증 완료율은 예정 슬롯 수를 분모로 각각 계산한다. 진행률0%는 작업 상태이며 AI 추천률0%와 다르다.

슬롯의 원문/검증 상태는 기존 관측을 참조하여 조회 때 계산한다. 미측정 슬롯은 실패/제외와 사유를 기록하고 재포함할 수 있다. 수집 후 제외는 7-1 검증 거부로 이력을 남긴다. PAUSED/IN_PROGRESS 상태와 시간·요약·변경 이력은 저장하므로 브라우저를 닫고 다시 이어갈 수 있다. 미측정이 남으면 COMPLETED 전환을 거부한다.

## 7. 분석 지표 및 Snapshot

분석은 고정30개 질문, 해당 Pre-Scan studyId, BASELINE, 선택 플랫폼, 고정 관측 방식에만 한정한다. 플랫폼별로 각각 계산하여 혼합 추천률을 만들지 않는다. 고객 언급·추천 후보·공식 사이트 인용·Query Coverage·경쟁사 언급과 의도별 차이를 저장한다. 공식 인용은 해당 지도에서 사용자가 확인한 URL의 호스트를 기준으로 한다.

미검증/거부/DEMO/부정확/내부 전용/검색 미확인/업체 식별 미완료 등은 확정 표본에서 제외한다. 분자/분모·사용 질문/응답 ID·제외 ID/사유를 저장하고 데이터가 없으면 null 및 “검증된 관측 데이터 없음”이다. 등록120을 실제120관측으로 쓰지 않는다. Query Coverage는 실제 검증 관측 질문을 분모로 한다. 검증 상태 필터의 UNVERIFIED/REJECTED는 내부 목록이며 확정 성과 통계를 만들지 않는다.

`PreScanSnapshot`에는 고객 기초 정보, 고정 질문 세트/선정 이유, 플랫폼, 검증된 관측 기간, 플랫폼/의도별 정의·분자·분모·응답 ID, 경쟁사, 핵심 격차, 출처·증빙 ID, 제한, 진행/미측정/제외 상태를 저장한다. Snapshot 생성마다 새 ID로 append하고 기존 payload를 수정하는 API는 없다. 고정 시 해시를 확인한다. 원문은 기존 응답 ID로 연결하고 Snapshot에 다시 복사하지 않는다.

PostgreSQL JSONB의 키 순서/소수 표현 차이를 고려하여 키를 정렬하고 표시 비율의 소수 표현을12자리로 정규화한 SHA-256을 사용한다. 정확한 정수 분자/분모는 유지한다. 관측 재검증/질문 변경 후에도 이전 Snapshot 데이터/해시는 유지된다. Snapshot은 고객 비공개 내부 자료이며 검증 근거 등 내부 필드를 포함할 수 있어 외부 PDF에서 그대로 출력하지 않아야 한다.

| 13 고정 Snapshot | DB 재조회 해시 재현/고정, 이후 질문·검증 변경 불변 단위 시험 |
| 14 1~6 유지 | 기존 단위/E2E 전체 회귀 |
| 15 7-1 유지 | 기존 보고서 E2E, 영속 health/백업 복원/최종 보존 대조 |
| 16 외부 AI0 | OpenAI/Gemini 차단·mock transport 시험, 실행 환경 두 플래그false |

첫 단위 실행이 Windows 샌드박스 경로 접근 때문에 시작하지 못하여 허용된 실행으로 재시도했다. DB 통합의 Snapshot 부동소수점 비교 실패를 정규화/해시 재현으로 수정하고 전체 재검증했다. 신규 E2E의 Snapshot summary 선택자가 버튼까지 매칭하던 시험 오류도 정확한 summary 선택으로 수정했다. 실제 실행 없이 성공으로 표시한 시험은 없다.

## 10. 외부 API 호출 여부

`LIVE_AI_ENABLED=false`, `FREE_GEMINI_ENABLED=false`를 유지했다. 유료·무료 외부 AI API 호출은 **0회**. 질문 생성/선정은 로컬 규칙, 시험 관측은 LOCAL MOCK이다. 플랫폼 링크는 제공하지만 시험이 링크를 눌러 외부 AI에 질문하거나 실제 데이터를 수집하지 않는다. API 키를 출력하지 않았다.

## 11. 미구현·제한 및 사용법

- 자동 질문 생성은 치과 우선이다. LEGAL/BRAND/ECOMMERCE는 확장 구조만 준비했고 각 업종의 자동120 템플릿은 미구현이다.
- 규칙 유사성/부적합 판정은 후보 검토 도구이며 외부 의미 모델이나 실제 검색량 검증을 대체하지 않는다. 검증은 사람의 출처 대조 기록이다.
- CSV는 기존 제한에 따라 한 번에50개/3MB 이내다. 미측정90행 양식은 나누어 입력하고 원문/시각 등 빈 필드는 실제 수집 후 채운다.
- 고정/저장된 Snapshot을 외부 보고서로 직접 공개하지 않는다. 실제 고객 조사/성과 증명은 이번 시험에서 수행하지 않았다.
- 2페이지 PDF, Pilot/유료 계약, Benchmark 판매, SaaS 과금, 제휴 포털, 무단 자동 수집은 개발하지 않았다.

앱에서 AI 질문 지도→잠재고객 등록/선택→지역·확인된 서비스·공식 URL 확인→생성→대표 질문 선정·30확정→무료 Pre-Scan 생성→관측 진행 현황에서 수동/CSV 수집·검증→분석 결과에서 Snapshot 생성·고정 순서로 사용한다. 연구소와 같은 원문·검증 기록을 사용한다.

## 12. 7-3 영업 PDF 준비 상태

고정 질문 세트, 관측/증빙 연결, 플랫폼별 검증된 분자/분모, 경쟁사, 한계·미측정/제외가 담긴 Snapshot을 제공한다. 7-3은 이 비공개 Snapshot에서 외부 공개 가능한 필드만 선택하고 개인정보/검증 메모를 제거하여 PDF에 표시해야 한다. Snapshot 버전/해시·표본 범위를 표시하고 데이터 없는 결과를 성과로 꾸미지 않는 기준을 이어갈 수 있다. 7-3 개발은 시작하지 않았다.
